# Architecture and compatibility

## Module boundaries

| Module | Responsibility |
| --- | --- |
| `capture.ts`, `capture-controller.ts` | Cooperative visible DOM traversal, mutation scheduling, route generations, cumulative visible text, content hashes |
| `adapters/`, `weibo.ts`, `twitter.ts`, `twitter-url.ts`, `post-buttons.ts` | Site selector priorities, validated post permalinks and shared manual-save buttons for Weibo/X; no server API scraping |
| `database.ts` | Original IndexedDB schema compatibility, atomic writes, incremental index migration, expiration |
| `text.ts`, `identity.ts`, `aliases.ts` | Segmentation, normalization, stop words, stemming, explicit aliases, URL identity, snippets |
| `search.ts`, `search-query.ts`, `ranking.ts` | Shared query syntax/predicates, indexed keyword retrieval, bounded verification, field weights and proximity ranking |
| `SearchView.tsx`, `SearchHelp.tsx`, `Highlight.tsx` | Shared search UI and bilingual syntax guide for popup, side panel and tab; original spelling remains visible |
| `SavedTextPreview.tsx`, `MarkdownText.tsx`, `markdown.ts` | Original-text/Markdown preview toggle, lazy bundled Markdown/math/code rendering and DOM sanitization |
| `SettingsView.tsx`, `settings-ui/*` | Settings orchestration and separate capture/search/data/connection/about sections |
| `settings.ts`, `presentation.ts` | Legacy settings conversion, defaults, toolbar behavior and explicit presentation switches |
| `backup.ts`, `remote.ts` | Import/export/encrypted backups; optional metadata endpoint and synthetic connection test |
| `background.ts`, `search-companion.ts` | Chrome API events, sender validation, bookmarks, history, omnibox and search-engine integration |

Plasmo entrypoints live under `src/`. The original icon and manifest translations remain under root `assets/`, as required by Plasmo. No background keepalive page, remote scripts, eval-based execution or Wasm tokenizer is required. The new runtime dependencies are bundled into the extension. Development uses npm and its single committed lockfile.

## Capture

The controller observes text/child and visibility-affecting attribute changes, frame loads, scrolling, resizing and SPA navigation. Captures coalesce with a 700 ms debounce, at least 2.5 seconds between normal passes, and a 5-second upper scheduling interval on busy pages. DOM traversal yields after approximately 8 ms of work. Generation checks discard results from a route that changed during capture. The background verifies the sender's current document and URL before accepting a snapshot.

`content-context.ts` detects invalidated content-script worlds after an extension update/reload. On the next callback it disconnects capture/site observers, cancels timers, removes DOM event listeners and clears injected controls. Async reads check the context again before writes or DOM updates; route configuration rejections are handled. Browser language is cached so in-flight UI callbacks do not repeatedly access an invalidated Chrome API. Refreshing an old webpage activates the new script; saved IndexedDB records remain intact.

`adapters/sites/` supplies explicit content containers for the sites covered by the 100-site live audit and later rounds. Isolated adapters use the first selector that has visible matches, retaining all matching article sections unless `maxRoots` limits them. They omit site chrome/known advertising containers and wait when their article root has not loaded, without appending a whole-body fallback. Unadapted pages retain the general visible-DOM fallback. Some rules are path-limited, such as Bilibili articles and Internet Archive's About pages. Internet Archive's rule searches open shadow roots and registers those roots for subsequent mutation observation. Same-origin frames and other open shadow roots within captured content remain supported. Inputs, editable fields, extension controls and hidden responsive variants are excluded. `capture-policy.ts` suppresses identified challenge/error screens without bypassing them. Generic image alt text is not repeated when its parent already contains the same label.

Static Media articles contain multiple body sections and append unrelated articles during scrolling. `rootIdentity` compares the current URL's article ID with the rendered article heading, retaining all current sections and following later SPA navigation. Shared Hearst rules exclude newsletter and membership shadow components without disabling legitimate shadow content elsewhere. Host-scoped `stopBefore` and `excludeBlocks` handle observed terminal recommendations or exact promotion paragraphs when a distinct structural container is unavailable. The controller observes the `Document`, so an access-check page replacing its entire HTML element does not orphan mutation observation.

BBC, Kotlin documentation and Search Engine Journal use a separate `document_start` entrypoint because visible articles can precede DOMContentLoaded when a blocking or deferred script stalls. The ordinary `document_idle` entrypoint excludes those URLs, so controllers install once. Other sites retain the existing injection timing.

Already-seen blocks survive virtualized list removal within a page session. A route change resets this snapshot; ordinary anchors retain the page identity. Isolated captures carry an optional `captureProfile` (adapter ID plus rule revision). Database writes merge across visits only when the profile matches: the first clean recapture replaces a legacy whole-page mixture and reindexes it while preserving the record ID and bookmark state; subsequent visits with the same profile continue accumulating loaded discussion text. No database schema bump or bulk deletion is needed. Metadata-only updates preserve the profile. Future rule changes that require cleaning existing captures should increment the profile revision.

The second 100-site audit added additional site rules, now organized by domain in `adapters/sites/`. Scoped capture revision 2 preserves the current snapshot verbatim, including repeated table cells and code lines; `captured-snapshot.ts` appends previously seen blocks absent from that snapshot. This applies both within a session and across database saves. The generic virtualized-list capture still uses its existing block accumulation. Mintlify document cards have narrow exceptions for visually rendered `aria-hidden` link wrappers; CSS-hidden content remains excluded. Can I use selects feature hosts inside nested open shadow roots and observes their updates. Generic image placeholders such as `Image` are omitted while descriptive alt text is retained.

Changed text is tokenized and written once in an awaited transaction. Identical text avoids reindexing. Long newly captured pages are capped at one million characters, with a visible partial-capture indication. This limit does not apply to original text during migration.

Weibo and X have independent saving switches (`weiboSupport`, `twitterSupport`) and page-capture switches (`weiboAutoCapture`, `twitterAutoCapture`). Both page-capture switches default to false, including migrated settings: manual post saves are still accepted independently of the global automatic capture switch. Disabling site saving hides buttons and blocks both manual and automatic text capture. The controller and worker both enforce the page-capture policy, including bookmark-triggered capture. Manual saves validate the current sender and target site, respect sender/target exclusions, use the post permalink, and mark the record bookmarked. X aliases and media links are canonicalized to HTTPS x.com status URLs. No extra permissions or database schema changes are needed.

## Search semantics

ChatGPT, Gemini and DeepSeek use `chatgpt.ts`, `gemini.ts` and `deepseek.ts` as DOM adapters, `chat-save.ts` for shared UI/status/completion-gated capture, and `chatgpt-data.ts` for strict per-site URL/metadata validation and ordered merging. Gemini uses user-query/model-response roots, excludes duplicate screen-reader labels and gates on aria-busy/stop controls and response actions. DeepSeek uses stable virtual-list item keys and requires final response content and its action row before capture. Both have separate enabled-by-default support and automatic settings. The adapter supports legacy `data-message-author-role` and current message-bubble/assistant-markdown markup observed in Chrome. Generic body capture is always bypassed on all three chat sites, so it cannot save drafts, navigation or partial streams. The dedicated automatic setting defaults on and is independent of general page capture. Generation-state attributes, streaming markers and visible stop controls block assistant writes; a stable-text interval follows completion. Sender validation requires the same current conversation and enforces the feature, automatic setting, exclusions and incognito restrictions again in the worker.

One canonical conversation URL identifies one record. Optional structured conversation metadata lives in the existing contents store, without a database version change. Messages merge atomically by message ID and are ordered by the site's turn position. Repeat text in distinct turns is retained, while edits replace the matching turn. The same transaction builds the searchable plain-text transcript. Saved-text preview defaults to escaped React text in role-based bubbles, with an optional Markdown toggle shared with ordinary pages. JSON backups and index rebuilds preserve message metadata; older imports cannot overwrite newer conversation text. The one-million-character capture bound is surfaced through the existing partial-content notice. Only loaded DOM messages are read; no private chat service API is called. Buttons append to native bottom action rows so native visibility rules apply. The composer reserves a right gutter for an external save icon. The worker returns stored message hashes for current-conversation status on refresh; edited text is compared after visible-text extraction.

The Markdown module is loaded only on first use. markdown-it parses standard Markdown plus tables/strikethrough/linkification; @mdit plugins add disabled task checkboxes and KaTeX dollar/bracket delimiters. Fenced code uses highlight.js common languages (unknown languages and blocks over 20,000 characters remain escaped code). Source HTML stays literal; KaTeX trust is disabled and expansion/size are bounded. DOMPurify sanitizes the final HTML, MathML and SVG before insertion. Links use HTTP(S)/mailto only and open with noopener/noreferrer; images use HTTP(S), lazy loading and no referrer. Relative URLs resolve against the source page, never the extension document. Scripts, styles and fonts are local extension assets. The toggle is per dialog and does not write data or alter the export pipeline.

- ICU `Intl.Segmenter` word boundaries plus CJK unigram/bigram indexing avoid requiring a downloaded model. A longer CJK query can seed from a bigram and is verified against contiguous text, covering context-dependent segmentation.
- `stopword` English/Chinese dictionaries supplement local function-word rules. Negation remains meaningful. Stop words are retained in the index and in quoted queries. An all-stop-word query can still be searched.
- `stemmer` provides English Porter stemming. Exact terms rank above stems, aliases, prefixes and edit-distance-one matches. Typo candidates come from a persisted deletion dictionary. Adjacent letter transpositions are included; Chinese typo/pinyin correction is not claimed.
- OpenCC converts Chinese runs for indexing/search only. Saved text is untouched. Latin accents, width and case normalize; English contractions and dotted initialisms tokenize consistently.
- Explicit alias groups handle examples such as JS/JavaScript, CPU/central processing unit/中央处理器 and U.S.A./USA. Ambiguous initials such as PM are not guessed. Quotes disable alias, prefix and typo expansion and verify the complete phrase.
- The rarest term seeds candidate retrieval. All terms are checked against each candidate's complete token lists, fixing the false negative caused by intersecting separately truncated common-word lists. Work is capped at 5,000 candidates and the UI asks for more specific keywords when capped; this is not an unlimited exact total.
- Structured queries share `search-query.ts` with open-tab search: exact phrases, word `*`/`?` globs, `site:`, URL substring/glob matching (`url:`/`inurl:` and recognized pasted URLs), `intitle:`, `intext:` and `-` exclusions. Field operators override the selector. Literal phrases are normalized and boundary-checked within each field, never across a title/URL concatenation. A URL's `?` remains literal. Glob evaluation is iterative rather than a user-generated backtracking regex.
- Structured constraints filter page metadata first, then inspect bodies in batches of 64. Their 5,000-match cap is applied after verification, allowing a rare site, title or wildcard match beyond 5,000 nonmatching pages to survive. Body-only phrases and leading wildcards can require a batched scan of the archive; this path prioritizes exact syntax over index-token approximations and does not change the database/index version. Results above the cap are labeled as limited.
- Ranking combines field weights (title 5, body 1, URL 2), an approximate inverse document frequency, saturated occurrence counts and the shortest window containing matched terms. Whole-title/phrase matches are boosted, very long documents are lightly penalized, and recency contributes only a small tie-breaker. This is a documented heuristic, not a claimed semantic or neural model.
- If a plain keyword query of at least three terms has no complete match, a clearly labeled fallback requires at least two terms and 60% coverage. It does not discard negation, and queries with structured constraints never use this fallback. Snippets are built for the requested result page only. Full bodies are read in bounded batches, rather than loaded for the entire archive.

## Upgrade contract

The extension retains `PageDatabase` and the v1 `pages`, `contents`, `vectors` stores. The v2 schema adds URL/index metadata and a persistent token dictionary. Legacy primary keys, duplicate URLs, unsupported legacy URLs, timestamps, full original text and bookmark flags remain intact; unsupported URLs cannot become executable search links. Old optional auxiliary rows are preserved during migration, without retaining their former integration code.

`indexVersion` is separate from the IndexedDB schema version. Current token format is 3. Batches of 25 records commit independently, and alarms resume interrupted work. The original `persist:fulltextbookmark` key remains untouched; JSON-stringified Redux fields are converted to `settings.v2`, including false booleans and zero retention. Index construction never requests an export/import. Expiration pauses for 24 hours after the original-schema upgrade, then resumes the existing retention rule.

Settings preserved: `storeEveryPage`, `bookmarkAdaption`, `weiboSupport`, `searchEngineAdaption`, `showOnlyBookmarkedResults`, `tempPageExpireTime`, `maxResults`, `forbiddenURLs`, `remoteStore`, `remoteStoreURL`, `remoteStoreKey`, `remoteStoreEveryPage`. Address-bar search keeps `kw`, with a new explicit enable setting. About/contact/donation links remain available. Removed AI settings are ignored. New language, fuzzy matching and default presentation preferences use compatible defaults.

The default icon action opens the side panel. Users can select popup or search tab in Settings. Explicit switching carries the query without changing that preference. Popup geometry uses screen bounds, not its initially small `100vw/100vh`, to guarantee the requested 400 × 600 size on a sufficiently large display. A missing side-panel API falls back to popup. Minimum supported Chrome is 127 for general availability of programmatic popup opening.

Settings edits use validated per-field patches. Switches/selects commit immediately; text/number drafts debounce for 600 ms and flush on blur/pagehide. Invalid drafts stay in the editor with field errors and a dismissible alert, without replacing stored values. The worker serializes patches and validates them against current settings before writing, so rapid edits do not overwrite one another. The full `save-settings` message remains available for existing internal clients. `settings-validation.ts` is shared by the editor and worker.

## Dependencies and build constraints

Direct packages were checked against npm latest on 2026-11-08. Supported transitive fixes are pinned via npm overrides. `npm audit --omit=dev` reports zero runtime vulnerabilities. The Plasmo 0.90.5 build chain still pins Parcel 2.9.3; seven low/moderate development-only audit findings remain. Forcing its reporter to Parcel 2.16.4 produces plugin compatibility errors, so that incompatible override is not shipped. No such reporter code is part of the production extension. `npm audit fix --force` proposes a much older Plasmo release and is not an acceptable upgrade.

### Extending site adapters

`adapters/types.ts` defines the contract; `define.ts` provides article/application constructors; `registry.ts` registers domain modules and resolves host/path specificity; `roots.ts` discovers visible DOM roots; `noise.ts` holds common structural exclusions. Add rules to a subject module in `adapters/sites/`, not a numbered audit file. Stable IDs and per-rule revisions control saved-content replacement independently of file layout. See [the extension guide](../src/adapters/README.md).
